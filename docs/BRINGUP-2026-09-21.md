# Bring-up log: Nix integration audit (2026-09-21)

No device commands or writes were performed.

* `nix flake check --no-build` passes for the liuqin BSP, including the
  example and demo configurations, boot image derivations, rootfs image
  derivations, installer, smoke initramfs/image, and the `uboot-build`
  wrapper.
* A real `nix build .#bootimg` completed. `unpack_bootimg.py` confirmed
  Android header v2, kernel offset `0x8000`, DTB offset `0x1f00000`, and an
  empty ramdisk. The fixed-output hash for the AOSP archive was corrected
  after the old mirror content changed; the per-file checks remain enabled.
* A real `nix build .#smoke-initramfs` and `nix build .#smoke-bootimg` completed. The
  smoke image contains a static aarch64 BusyBox and resolves the `linux`
  partition by GPT `PARTNAME` from sysfs (no udev dependency). It only mounts
  read-only and never formats or writes storage.
* A real `nix run .#uboot-build` completed. The checked-in U-Boot compiled and
  `package-boota.sh` produced `liuqin-dualboot/out/liuqin-uboot-boot-a.img`
  (729088 bytes), with an 8 MiB decompressed payload, text offset 0, flags
  `0xa`, a 1783-symbol stock union and all DTB/framebuffer assertions passing.
* `tools/install.py --target linux` no longer attempts the userdata backup
  loop (that was an actual control-flow bug: `args.backup` is intentionally
  absent for the linux target). The backup/fetch path remains restricted to
  the destructive whole-userdata target.
* The smoke kernel now builds the USB control path in, with
  `CONFIG_USB_DWC3_GADGET=y`, `CONFIG_USB_CONFIGFS=y`, and built-in NCM/ECM.
  The smoke initramfs binds NCM (falling back to ECM), assigns `usb0` the
  `192.168.7.2/24` address, starts DHCP and a diagnostic telnet listener on
  port 2323, but only after proving UFS block devices are read-only. This is a
  control/observation channel, not a partition installer; GPT writes remain
  in U-Boot's geometry-asserted command and rootfs deployment remains the
  host-side fastboot installer.
* The smoke PID 1 was reviewed for the no-udev environment: it resolves
  `PARTNAME=linux` from sysfs, locks every `/dev/sd*` node read-only before
  exposing USB, and holds instead of rebooting. The host can use the USB
  NCM/ECM telnet channel for observation. No partition utility or write
  operation is run automatically; all UFS nodes start read-only. An explicit
  `enable-storage-writes LIUQIN-ENABLE-WRITES` command can unlock them for a
  deliberate BusyBox operation; GPT carving is performed explicitly with the
  static `sgdisk` tool after measurement and backup.
* A real `demo-bootdir` build was attempted. The current host is x86_64
  without an aarch64 executor, so Nix correctly stopped at platform mismatch
  while building the aarch64 initrd. Use qemu binfmt or an aarch64 builder for
  `demo-rootfsImage` and `demo-bootdir`; this is an environment prerequisite,
  not a device failure.
* `u-boot/build.sh` now resolves its default environment file and output
  directory relative to the repository/script, so invoking it through the Nix
  wrapper cannot accidentally select a caller-relative shadow file.
* The dual-boot install design remains: the live image's static `sgdisk` is the
  explicit, operator-driven GPT maintenance tool; NixOS emits an ext4 image
  containing both the root filesystem and `/boot`; the host installer writes
  only `linux`.

The device is intentionally untouched because the current ABL lockout makes
any persistent boot experiment unsafe; validation must begin with RAM boot
once authorized recovery has restored a working ABL path.

The host installer now preflights `max-download-size` in addition to the
measured target partition. Since the generated ext4 artifacts are ordinary
non-sparse files, a file larger than that fastboot DATA limit is rejected
before backups or writes rather than being allowed to fail mid-transfer.
The flake also exposes `rootfsImageSparse` and `demo-rootfsImageSparse` using
Android's `img2simg`; the installer uses `simg2img` only for local ext4/label
validation and leaves the sparse artifact intact for AOSP fastboot's transfer
resparsification. Sparse logical capacity is read from its header for the
partition-size check, so the compressed transfer size cannot hide an
over-sized expanded filesystem.
It also rejects U-Boot's fastboot endpoint by its diagnostic `build` variable;
rootfs writes are restricted to stock ABL fastboot, where the large-image
transfer path is the one that has been validated.

## Update 2026-09-22

The smoke image now has a host-operable USB2 NCM/ECM diagnostics channel. The
kernel build was rerun successfully after selecting `USB_DWC3_GADGET=y`; the
final config also contains built-in `USB_CONFIGFS`, NCM and ECM. The init
script was checked with `sh -n`, rebuilt into `smoke-bootimg`, and reviewed to
ensure it locks all `/dev/sd*` nodes before exposing the gadget. No device was
connected or written.

The live shell now exposes an explicit `enable-storage-writes
LIUQIN-ENABLE-WRITES` command for deliberate BusyBox block operations. It
starts with all UFS nodes read-only, requires the exact confirmation token,
and verifies the resulting state; it never partitions or formats. GPT carving
uses the live image's `sgdisk` after an explicit GPT backup and verification;
the current U-Boot safe profile intentionally has no generic GPT partition
writer; its narrowly-scoped A/B slot metadata helper is separate.

The remaining historical research document `NIXOS-ANDROID-RESEARCH.md` was
given an explicit 2026-09-22 supersession banner so its old Android handoff
proposal cannot be mistaken for the current ABL/`boot_a` flow.

The final cross-repository review found that U-Boot commit `5482561f` removed
`liuqin_mklinux` from the current read-only safe profile, while several NixOS
comments still named it. Those references were removed. The smoke initramfs
now includes a static aarch64 `sgdisk` binary for explicit, operator-driven
GPT maintenance; `/init` never invokes it, and the initial UFS lock remains
read-only. It also includes `liuqin-gpt-carve`, which performs a dry run by
default, creates a GPT backup, asserts the measured userdata geometry and
verifies the post-write table only when the explicit
`WRITE-LINUX-GPT USERDATA-FS-SHRINK-VERIFIED` tokens are supplied after an
external F2FS shrink. The rebuilt archive was inspected and contains both `bin/sgdisk`
and `bin/liuqin-gpt-carve`.

The U-Boot wrapper was rebuilt again against that exact safe-profile HEAD;
`package-boota.sh` still passed the Android header, 8 MiB payload, text-offset,
DTB and symbol-union assertions. The generated artifact remains RAM-boot-only
until the device is recovered.

The installer identity audit was tightened again: it now rejects the current
U-Boot fastboot endpoint when its diagnostic `build` variable is present,
forcing image writes through stock ABL fastboot. A small regex unit check and
the installer derivation build passed; no fastboot process was started.

During this review an actual installer bug was found and fixed: the ext4
magic read had accidentally been placed after the file context closed. The
read is now inside the context manager, and the installer derivation was
rebuilt successfully afterward.

The final geometry review compared the NixOS contract with the stock dump and
U-Boot logs: the new `linux` partition belongs to LUN0 (`scsi 0`), while
`boot_a`/`boot_b` and their A/B attributes belong to LUN4. U-Boot's
`boot_linux` therefore uses `part number scsi 0 linux`, as intended; the LUN4
distinction must not be copied into the Linux loader. Any sector numbers in
historical documents are now treated as evidence only, and the active NixOS
path requires live measurement plus the GPT backup before carving.

The standalone `examples/demo` consumer flake now exposes the sparse rootfs,
smoke boot image and U-Boot wrapper as well as the normal rootfs/bootdir/bootimg
outputs, so a copied consumer has the same bring-up toolchain. Its evaluation
and the BSP flake checks pass; actual rootfs closure construction still needs
an aarch64 builder or qemu binfmt on the host.

The host installer now spaces every `fastboot getvar` probe by 1.1 seconds.
This follows the ABL evidence in `DEBUGGING.md`/the incident report: its
fastboot endpoint can drop consecutive answers even for its own variables, so
the installer must not run identity and geometry probes back-to-back.

The GPT safety review found that the stock userdata filesystem is encrypted
F2FS. `sgdisk` cannot shrink that filesystem, so `liuqin-gpt-carve` now refuses
the write path unless the operator supplies both
`WRITE-LINUX-GPT USERDATA-FS-SHRINK-VERIFIED`; Android/recovery must perform
and check the clean, unmounted F2FS shrink first. The audit capture shows
`resize.f2fs` refusing an unclean image. The live image now carries static
aarch64 `fsck.f2fs` and `resize.f2fs` binaries so recovery work does not
depend on the stock userspace. They are never called by PID 1 or the GPT
helper: an unmounted clean check, explicit resize, and clean follow-up check
remain a separate reviewed operation before the GPT confirmation token is
valid.

The evidence is retained in
`liuqin-audit/out/tvm-ident-20260906/device/dmesg-after.txt` (and the matching
`tvm-getstate-3` capture): `resize.f2fs` reports the Android F2FS geometry and
then exits with “Mount unclean image to replay log first”. This is why the
operator must perform a clean/replay pass before the shrink and must verify the
new filesystem geometry before allowing the GPT helper's second token.

The utilities use nixpkgs' static aarch64 `f2fs-tools` with its supported
`--without-selinux` configuration. The default static closure failed to link
libselinux's PCRE2 references; SELinux integration is irrelevant in this
standalone initramfs. The override builds successfully, and the smoke archive
contains the static `fsck.f2fs` multicall binary plus its `resize.f2fs`
symlink and the gated `liuqin-f2fs-shrink` wrapper. No filesystem image or
device was resized during host validation. After a permitted resize, the
wrapper also reads the F2FS superblock and checks `block_count` against the
requested sector target and the reported filesystem block size before it
returns success.

The GPT helper also now requires the measured source entry to be named exactly
`userdata`, in addition to matching its measured start/end, type GUID and
unique GUID. It will not silently rename an unrelated entry.

The GPT helper received a correctness fix during the final audit: `sgdisk
--info=N` returns status 0 even when it prints `Partition #N does not exist`,
so the free-number check now matches that diagnostic instead of trusting the
exit status. This was verified against a synthetic GPT image with nixpkgs'
`sgdisk`; no real block device was opened.

The kernel command-line audit also corrected a latent bring-up mismatch. The
local U-Boot log proves that `simplefb_driver_init` alone is insufficient:
`arm_smmu_init` and `disp_cc_sm8450_driver_init` can reprogram ABL-owned display
state and blank the panel. The NixOS module and the standalone boot.img
default now carry the exact combined `initcall_blacklist` value.

The smoke BusyBox also contains `httpd` and `base64`; the live backup is not
pretended to be persistent. The operator can serve `/run` with
`busybox httpd -f -p 8080 -h /run` and retrieve the backup over the isolated
USB network before rebooting.

The static aarch64 BusyBox used by the smoke image was checked under
`qemu-aarch64`; every applet used by `/init` (`mount`, `umount`, `blockdev`,
`ip`, `udhcpd`, `telnetd`, `blkid`, `findfs`, and `dmesg`) is present. The
installer's endpoint fence was also exercised offline with representative ABL
and U-Boot `getvar build` replies: the former is accepted and the latter is
rejected before any write path is reached.
